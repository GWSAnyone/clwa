## engine-bridge: Мост лор↔движок — состояние и роадмап

**Значит, лор-сторона моста почти закончена. Не построена инженерная сторона: артефакты, которые превращают лор в данные, которые читают M8/M9-реестры.** Роадмап ниже строит конкретные мост-артефакты, а не «развивает лор».

### Ключевые находки/предупреждения
1. **M8/M9 НЕ блокируют друг друга по реализации, но мир блокирует обе.** Тип I (self-override + plasticity-cost) требует M8 Seam A + M9 P1/P4; Тип II (cross/zone) требует M9 P3/P4. Полный мир «выразим после M9-P4».
2. **«Никто не делает оба» — конвенция модуля, НЕ engine-инвариант.** Обе спеки честно фиксируют: движок не enforce'ит. Гибрид класса игрока (§4.5) и гибрид формы Orin (form: Set{ambient,directed}) опираются на это — module-бухгалтерия.
3. **Player-execution-эмиссия onActionExecuted — общий долг M8↔M9 и реальный блокер bilateral-кристаллизации игрока.** validatePlayerAction — мёртвый код; живой player-path не несёт affordance-identity. Пока эта точка не приземлена — Seam A для игрока латентен. Самый критичный технический риск для «кристаллизация игрока = стержень прогона».
4. **attention-scaling — единственная незакрытая дыра genre-neutral схемы.** scaling: 'attention' (DEESSE) в CONCEPT §6.4 назван «новым источником», но ни M8, ни M9 не специфицируют, откуда движок читает attention-сигнал (нет примитива, как beliefs/relationships для belief/sentiment). Writer-only спойлер, но genre-neutral сторону нужно спроектировать или явно отложить.
5. **Страж масштаба соблюдён в мосте.** transfer/skim/bank — «весомое пунктирное событие», не атлас; два силуэта (Хаб/Сайт) = контент-силуэты, НЕ локации/ZoneState. Спека item-4 должна это удержать.

### Спойлер-дисциплина
DEESSE/R-0, «дожать травму», attention-scaling-носитель = writer/engine-only. item-6 трактует attention как абстрактный scalar-сигнал без лор-привязки в движке (INV-14): движок видит только scaling: 'attention' → opaque key, никогда «DEESSE».
