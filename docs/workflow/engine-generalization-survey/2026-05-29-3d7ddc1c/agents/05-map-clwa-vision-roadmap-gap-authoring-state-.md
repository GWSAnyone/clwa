## area

CLWA — Vision/Roadmap gap + Authoring state (Phase 3 engine subsystems & world/module tooling)

## universal

- Event system is fully content-agnostic. `WorldEvent`/`EventType` are plain strings (cg-types.ts:1-14), and event-registry.ts exposes ~40 fill-at-startup registries (event flags, categories, labels, mood shifts, belief creators, memory builders, step handlers, tick-phase handlers, discovery/day-advance/consequence-post handlers, secret-directive builders, etc.). A new module can introduce arbitrary event types with ZERO engine edits — this is the genuinely reusable core.
- Consequence Graph (CG v2) is a generic reactive cascade engine: `ConsequenceRule` + `RuleCondition` operate on op-codes ('trait','relationship','belief','has_capability','eq/gt/lt') over event payload + NPC state (cg-types.ts:16-60). Rules are pure data arrays (CRIME_CG_RULES) passed in at boot — any genre's cause→effect chains express here without engine changes.
- Personality→utility scoring is genre-neutral: OCEAN+H + Enneagram → `AffordanceWeight`/`AffordanceDefinition` (al.ts:51-160). Affordances are declarative data (CRIME_AFFORDANCES in affordances.ts, socialize in social/index.ts) with weights, resistTraits, moodWeight, stepTemplates, beliefModifiers — instinct prose is generated generically. Any drive (trade urge, hunger, ambition) can be modeled as an affordance today.
- Goal execution has universal primitives (move_to, interact, announce, wait) with everything else delegated to STEP_HANDLERS registry (event-registry.ts:379-414). Declarative `StepTemplate` with $target/$home/$extra interpolation means new action verbs are data + a handler fn.
- Beliefs, Relationships, Memory (Qdrant dual-store), Perception, Schedule, Clock/ProcessingQueue, Dialogue/TopicEngine, IL (player speech→structured intent) are all genre-neutral substrate. IL schema enums (speech acts, pressure types, claim sources, question topics, action verbs) are registry-driven (event-registry.ts:745-853) so a new module widens the player's verb space without engine edits.
- Module wiring is a single registration function (registerCrimeJusticeModule / registerSocialModule) called at server boot (server/index.ts:42-43). Engine never imports modules — dependency direction modules→engine is real and enforced by structure.
- Bilateral design is real: Player = Agent with isPlayer flag; same beliefs/relationships/perception pipeline. A new genre inherits player participation for free.
- World CONTENT authoring is data-driven JSON: NPC profiles (OCEAN+H, enneagram, role, secret, motive, schedule, shop), relationships, locations, secrets, topics, config — all loaded by world-loader.ts and editable in the World Editor (7 sections). Swapping the cast/map/relationships for a new setting needs no code.

## lockedOrLimiting

- AffordanceRequirement (al.ts:11-49) hardcodes crime-justice field NAMES into the ENGINE type: noGuardNearby, maxWitnesses, hasCrimeBelief, isCriminal, isWanted, hasDetainedNpc, hasWitnessBelief, notPerpetrator, hasSuspicionBelief, deductionBelowThreshold. Engine `checkRequirements`/`checkRequirementsReactive` (al.ts:332-371) directly branch on req.notGuard/isGuard/isInvestigator/canSentence. The registry escape hatch (REQUIREMENT_CHECKERS, al.ts:288-298) exists but is bolted ALONGSIDE these hardcodes — a clear double-standard. An Economy/Politics module's requirements (hasCapital, isOfficeholder, atMarket) cannot be added as data; they need either engine edits or abuse of the generic checker. This is the single biggest INV-14 leak.
- AgentProfile capability flags are hardcoded crime-justice roles: investigator, detersCrime, canSentence (agent-types.ts:101-106). These are first-class typed booleans the engine reads directly (e.g. al.ts:332-335, findByRole deterrence at al.ts:305, post-target noGuardNearby). A new genre's roles (merchant-license, faction-leader, voter) have no home except piggy-backing on these crime flags.
- findByRole in the ENGINE (al.ts:269-280) auto-enriches every target with crime belief vars (perpetratorName/affectedName/crimeLocation/crimeType via isTransferable + getEventLabelSafe). Generic role lookup is laced with crime semantics; harmless-but-wrong for non-crime modules and a smell.
- post-target requirement checks noGuardNearby/maxWitnesses (al.ts:301-316) bake the crime concept of 'witnesses' and 'guard deterrence' into engine evaluation rather than a registry.
- AgentState carries crime-flavored transient fields (currentMotive, lastInteractionOutcome) but has NO generic slots for items/inventory, needs, or faction membership (agent-types.ts:132-170). Adding those subsystems will require new AgentState shape — an engine change, contradicting the 'no engine changes for new module' test.
- EventHandlerContext / TickPhaseContext expose crimeScenes, bodyDiscoveries, crime-scene templates and CrimeSceneTemplate (event-registry.ts:222-296, 668-700) as first-class engine concepts. 'Crime scene' is a generic 'investigable site' idea leaking as crime-named engine surface.
- BELIEF_SOURCE constants and default BELIEF_SOURCE_LABELS (event-registry.ts:312-338) ship body_discovery/testimony/evidence/deduction as engine defaults — investigation-flavored, though overridable.
- Authoring a SECOND module today = writing TypeScript (affordances.ts arrays, cg-rules.ts arrays, ~30 register*() calls like crime-justice/index.ts which is 1200+ lines). There is no data format or tool to declare a module — so the 'modules = data, not code' principle (ROADMAP Principle 3) is aspirational, not yet true for module DEFINITION (it is true for world CONTENT).

## gaps

- MISSING SUBSYSTEM — Inventory/Ownership (ROADMAP Phase 3): no Item/Container/Transfer types, no AgentState.items, no registry. Confirmed absent (grep for Item/Container/ownership found only unrelated UI hits). Unlocks: real Economy module (goods, money), physical evidence (plant the knife), crafting, trade, loot. Highest leverage — it is a dependency of Needs and of the Economy/Combat modules.
- MISSING SUBSYSTEM — Needs/Resources (ROADMAP Phase 3): no Need type, no NEED_DEFINITIONS registry, no affordance boost from critical need. Today motivation is only mood+personality+belief. Unlocks: Survival genre, organic economic pressure ('steals because family starving'), seasonal/scarcity dynamics. Depends on Inventory for physical satisfaction.
- MISSING SUBSYSTEM — Factions/Groups (ROADMAP Phase 3): no Faction type, no membership on AgentState, no FACTION_TYPES registry, no inter-faction sentiment/reputation. Today only 1:1 relationships exist. Unlocks: Politics module, organized crime, families-as-actors, guilds, territory. Blocks any genre where the unit of action is a collective.
- MISSING SUBSYSTEM — Trauma Layer (ROADMAP Phase 3): no TRAUMA_RULES registry, no permanent OCEAN+H baseline shift. PM exists but personality is static. Unlocks: character arcs, Horror, deep Social, organic character development. Cheapest to add (extends existing PM, no AgentState shape change, no dependencies).
- MISSING TOOLING — no module-authoring path that isn't TypeScript. World Editor (tools/world-editor) edits only crime-world CONTENT (NPCs/relationships/motives/secrets/locations/topics/config). It cannot define affordances, CG rules, event types, needs, items, or factions. To build a different GAME (not just a different town) you must hand-write a module package. A declarative module manifest (affordances + CG rules + event metadata as JSON/TS-data validated against registry schemas) is the missing bridge between 'engine' and 'designer'.
- MISSING — generic capability/role system. Replace hardcoded investigator/detersCrime/canSentence with a data-driven capability registry so genres declare their own roles. Without this, every new genre's authority/role logic must reuse crime flags or edit the engine.
- MISSING — generic requirement DSL. AffordanceRequirement should be an open keyed map resolved entirely through REQUIREMENT_CHECKERS (+ engine-provided generic primitives like atLocation/duringPeriod/isMemberOf), removing the crime-named hardcoded fields. Listed in ROADMAP as 'trivial registry extensions' but currently blocked by the hardcoded interface + engine branches.
- MISSING — content modules themselves (Economy, Politics, Combat) per ROADMAP table; but these are downstream of the four subsystems + the role/requirement generalization above.

## extensionPoints

- Module registration: write a register<Name>Module() that calls into engine registries, then add one call in server/index.ts:42-43 (and tools/world-editor/server.ts:18-20 if it should drive editor dropdowns). Pattern: crime-justice/index.ts (full) and social/index.ts (minimal ~40-line example — the best template for a new module).
- Behavior space: push AffordanceDefinition objects into AFFORDANCE_REGISTRY and register a TARGET_FINDERS entry (al.ts) — declarative weights/steps, no engine code.
- Reactive cascades: pass ConsequenceRule[] data arrays (like CRIME_CG_RULES) to the CG engine; conditions use the generic op DSL (cg-types.ts:39-60).
- Event metadata: registerEventCategory/Labels/TypeFlags/MoodShifts/SceneTypes + registerBeliefCreator/MemoryTextBuilder/DiscoveryHandler/DeathEvents/PursuitEvents (event-registry.ts) — declare a new event type's full behavior as registrations.
- Custom actions: registerStepHandler(action, fn) for new goal verbs; registerActionVerbs to expose them to the LLM DO/WHY parser.
- Periodic & lifecycle logic: registerTickPhaseHandler, registerDayAdvanceHandler, registerConsequencePostHandler, registerInteractionResultHook, registerSecretDirectiveBuilder — module side-effects without engine edits.
- Player-facing intent: registerSpeechActs/registerPressureTypes/registerPressureHandler/registerQuestionTopics/registerClaimSources/registerILTradeVerbs widen the IL schema so players get new verbs in a new genre.
- Module-specific requirements (the escape hatch for the crime-hardcoded interface): REQUIREMENT_CHECKERS.set(key, fn) (al.ts:229) — used by crime-justice (modules/crime-justice/index.ts:65-91). Generic primitives (atLocation/duringPeriod/isMemberOf) belong here per ROADMAP.
- World CONTENT (not module logic): JSON files under worlds/<name>/ (npcs/*.json, relationships.json, motives.json, secrets.json, world.json, topics.json) loaded by world-loader.ts:146 loadWorld(); edited via World Editor (tools/world-editor, port 3001). New world = new folder, no code.
- SMALLEST set to enable a meaningfully different game: (1) Trauma Layer (cheapest, PM-only, no AgentState change) for character arcs; PLUS (2) generalize roles+requirements — convert investigator/detersCrime/canSentence into a capability registry and make AffordanceRequirement fully registry-resolved (remove crime hardcodes in al.ts:11-49,332-371). Those two alone let a designer build, e.g., a faction-free Social/Drama or Survival-lite game purely as a new module + world JSON. To reach Economy/Politics/Combat you then add Inventory (unblocks Economy/physical evidence/trade) and Factions (unblocks Politics/organized crime); Needs is the follow-on that turns Inventory into organic pressure. Authoring-wise, the highest-leverage single tool is a declarative module manifest so a module is data validated against registry schemas — closing the 'modules = data' gap that the World Editor only solves for world content today.
