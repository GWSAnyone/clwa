# map-registry-module-extension-contract-event

> Per-agent structured output (final answer). Raw `.jsonl` transcript alongside.

## area

Registry / module-extension contract (event-registry.ts + AL/CG/topic/evidence/IL registries) — can the engine host an Economy module with zero engine changes?

## universal

- EVENT METADATA is fully data-driven. EventType = string (cg-types.ts:3, no hardcoded union). Modules declare everything about their events via registries in event-registry.ts: registerEventCategory (grouping), registerEventLabels (display prose), registerEventTypeFlags{Batch} (transferable/informationOnly/subjectReacts/decayRate — engine checks BOOLEAN FLAGS not category names, lines 23-65), registerEventMoodShifts, registerGoalMoodBoost, registerEventGoalCleanup, registerEventSceneTypes, registerDeathEvents/isDeathEvent, registerPursuitEvents/isPursuitEvent.
- AFFORDANCE LAYER (al.ts) is a generic scoring+gating engine. AFFORDANCE_REGISTRY (al.ts:169) is an empty array modules push AffordanceDefinition into. Scoring is pure data: OCEAN+H weights, moodWeight, relationshipWeight, trustWeight, beliefModifiers, resistTraits, severity (1-10 → instinct texture in instinct-builder.ts:61, NOT crime-specific). Verbs reach the LLM via registerActionVerbs + getAffordanceIdsForVerb; volition.ts:605 merges ENGINE_ACTIONS (go/talk/wait/announce) with getAllRegisteredVerbs() — schema enum is built from the registry, no hardcoded action list.
- GOAL STEP EXECUTION is registry-extensible. goals.ts has only 5 BUILT_IN_ACTIONS (move_to, interact, interact_present, announce, wait — goals.ts:352); everything else dispatches to getStepHandler() (goals.ts:660). Modules add arbitrary step verbs via registerStepHandler. Declarative StepTemplate (al.ts:79) with $target/$home/$extra var interpolation means many goals need NO custom code at all.
- CONSEQUENCE GRAPH (cg-engine.ts / cg-types.ts) is genre-agnostic. ConsequenceRule.trigger and .consequence.type are EventType strings; RuleCondition.op is a generic set ('trait','relationship','belief','has_capability','is_public_place','eq','gt','lt') operating on event payload + agent state. Modules supply rule arrays; engine cascades them with no knowledge of domain.
- BELIEF / MEMORY pipeline is registry-keyed by consequence type: registerBeliefCreator + registerMemoryTextBuilder (BeliefCreatorFn/MemoryTextBuilderFn), registerSourceFlags (perpetrator/firsthand/concealment booleans), registerSourceCategory (semantic grouping), registerSourceDecayRates, registerSourceTransferWeights, registerBeliefSourceLabels. Engine never names a source — defaults exist (lines 312-318, 347-353) but are fully overridable.
- REQUIREMENT CHECKING is hook-based: REQUIREMENT_CHECKERS map (al.ts:229) is iterated generically (checkRegistryRequirements al.ts:288); modules register named predicates (isCriminal, hasWitnessBelief, etc.) without touching engine. AccusationResponse (il.ts:93) and BlockingGoalTypes (al.ts:236) are likewise registry-driven hooks.
- CONVERSATION/TOPIC engine is content-blind: TOPIC_SOURCE_REGISTRY (topic-engine.ts:93) + registerTopicGroupMapping with prefix matching and a 'casual' fallback (resolveGroupFromCategory). Speech acts, pressure types, claim sources, question topics, IL trade verbs all have register*/get* registries used for LLM constrained-decoding enums (event-registry.ts:748-853).
- EXTENSIBLE LIFECYCLE HOOKS, all generic and multi-subscriber: registerTickPhaseHandler (per-tick, rich ctx incl. eventStore/goalManager/locations), registerDayAdvanceHandler, registerEventHandler (per eventType), registerConsequencePostHandler (behavioral response after CG apply), registerInteractionResultHook, registerInteractPostHook, registerDiscoveryHandler, registerSecretDirectiveBuilder (prompt injection), registerPressureHandler. addMoodModifier callback (INV-06) is threaded into every context so modules never mutate mood directly.
- EVIDENCE LAYER (evidence.ts) is empty-registry: EVIDENCE_RULES[] + EVIDENCE_SOURCES map filled by modules; engine iterates rules matched by rule.trigger===event.type.
- STRUCTURAL MODULE BOUNDARY (INV-14) holds: grep for any import of @clwa/modules / ../../modules across the whole engine returns ZERO matches. Dependency arrow is strictly modules→engine.
- NO crime EVENT-TYPE string literals in engine executable code: grep for 'NPC_KILLED'|'GOODS_STOLEN'|'WANTED_STATUS'|... finds them ONLY inside /** */ and // comments (beliefs.ts:8, al.ts:108, world-types.ts:132, event-registry.ts:569, world.ts:1528). Likewise 'arrest'/'steal'/'guard' literals appear only in doc comments. The data plane is genuinely clean.
- CAPABILITY-FLAG behavior model (DD: role string is display-only): engine gates on agent.profile.investigator / detersCrime / canSentence (al.ts:332-335) and the isStatusActive/isStatusAbsent registries — not on role strings. NpcStatus is an open string type with registry-driven active/absent classification.

## lockedOrLimiting

- CRIME-SCENE SUBSYSTEM IS HARDCODED IN THE ENGINE, not a registry. world-types.ts:128 `interface CrimeScene` with fields `crimeType`, `perpetratorId`, `victimId`; world.ts:1488 `World.markCrimeScene()`, world.ts:1529 `World.processKill()`, world.ts:53 `onMurder` callback, world-types.ts:107 tick-result `murder` field, world-types.ts:109 `crimeScene`, crime-scene.ts:`createCrimeScene`/`getPassiveNoticeText` (exported from index.ts:206). The spatial-residue mechanic is genuinely universal (a fraud audit trail, a battlefield, a spilled-cargo smuggling scene are all 'scenes with examination points') but the engine hardcodes crime vocabulary into its public API and core loop. An Economy module can REUSE markCrimeScene (sceneType is a free string via registerCrimeSceneTemplate) but inherits crime-named symbols. LOCKING: the type names, not the logic.
- ENGINE AffordanceRequirement TYPE LEAKS CRIME CONCEPTS (al.ts:11-49). Typed fields hasCrimeBelief, beliefConfidence, isCriminal, isWanted, hasDetainedNpc, hasWitnessBelief, notPerpetrator, hasSuspicionBelief, deductionBelowThreshold are crime-justice-specific yet declared in the ENGINE interface. They are evaluated generically via REQUIREMENT_CHECKERS, so they work, but: (a) the engine type knows crime vocabulary (INV-14 spirit violation — DD says 'before every string comparison ask is there a registry'); (b) al.ts:294 special-cases `req.beliefConfidence` to build the minConfidence param — an Economy 'hasCapitalAbove' requirement with its own param has no equivalent path and would need an engine edit. The requirement-param plumbing is NOT fully generic.
- EmotionalPressure.type is a HARDCODED UNION in engine (il.ts:148): 'threat'|'bribe'|'flattery'|'guilt'|'intimidation'. A runtime registry exists (registerPressureTypes/getRegisteredPressureTypes, event-registry.ts:748) used for IL constrained decoding, so the TYPE and the RUNTIME registry can disagree. An Economy 'extortion'/'price_anchor' pressure would register at runtime but be untyped / fall outside this union — type-level lock.
- TradeIntent (il.ts:152) bakes economy assumptions into the ENGINE with comment 'weapon, armor, potion, food, general' and AgentProfile.shop / ShopItem{price} (agent-types.ts:107-118) live in the engine. This is a HALF-BUILT economy already embedded in the engine rather than supplied by a module — so a real Economy module would collide with / have to reconcile against pre-existing engine economy primitives (ShopItem, TradeIntent, IL trade verbs).
- isArrestTarget callback name (al.ts:192, volition.ts:143) is crime-named in the engine VolitionContext. Behaviorally generic (world.ts:1643 iterates getBlockingGoalTypes()), but the symbol bakes 'arrest' into engine API surface.
- DEFAULT belief-source labels/weights seeded with crime/justice values in the engine (event-registry.ts:312-318 BELIEF_SOURCE_LABELS 'found the body'/'deduced from clues'; :347-353 transfer weights; BELIEF_SOURCE const :332). Overridable, but the engine ships opinionated crime defaults rather than empty maps — minor smell, not a hard block.
- volition.ts:169 debug-log branch keyed on agent.profile.investigator — benign (logging only) but another instance of engine reading a crime-flavored capability flag directly.

## gaps

- NO ECONOMIC-STATE PRIMITIVE. There is no engine concept of fungible resources / inventory beyond AgentProfile.shop+ShopItem.price (a static price list, agent-types.ts:113). No balance/wallet, no quantity, no transfer-with-conservation, no ledger. An Economy module's TRADE/buy/sell/steal needs to move quantified value between agents; today it would have to stuff numbers into event.payload and reimplement accounting in a tick handler. RuleCondition ops ('trait','relationship','belief','has_capability') cannot read a numeric resource field — no 'gt' on agent inventory. This is the single biggest missing capability for a 2nd genre.
- AFFORDANCE SCORING IS PSYCHOLOGY-ONLY. AffordanceDefinition weights are OCEAN+H traits, mood, relationship sentiment, trust, beliefs (al.ts:114-164). There is no hook for SITUATIONAL/RESOURCE drivers (e.g. score SMUGGLING higher when debt high or profit margin large). beliefModifiers can fake some of this via belief confidence, but an economy needs price/scarcity/opportunity scoring inputs the engine doesn't expose.
- REQUIREMENT-PARAM PLUMBING NOT GENERIC. checkRegistryRequirements (al.ts:288) only forwards req.beliefConfidence as a param (al.ts:294). A module requirement that needs its own numeric param (e.g. minGold, minMargin) has no generic param channel — needs an engine edit. Should be a generic params bag passed through.
- POLITICS/COMBAT have even less. No faction/allegiance model (relationships are pairwise sentiment/trust, not group membership), no resource of 'influence/legitimacy', no HP/damage/combat-resolution primitive (combat today = processKill all-or-nothing, world.ts:1529). A Combat module has no graded-damage state to mutate; a Politics module has no group/faction entity.
- EVENT.payload IS UNTYPED Record<string,unknown> (cg-types.ts:13) and is the de-facto extension point modules lean on (perpetratorName, affectedTargets, releaseDay...). No per-module payload typing/validation — fine for one genre, fragile when multiple genres share the bus and read each other's payloads.
- SCENE/RESIDUE is crime-shaped (CrimeScene/examination points/perpetrator-victim). A generic 'world-state residue at a location' abstraction (of which crime scene is one instance) is missing — limits reuse for economy fraud trails, battle aftermath, political scandal sites without inheriting crime vocabulary.
- NO GENERIC 'capability registry'. Capability flags (investigator/detersCrime/canSentence) are hardcoded booleans on AgentProfile (agent-types.ts:101-106). A 2nd genre wanting new capabilities (canTrade, isFactionLeader, canSmuggle) must edit the engine AgentProfile type — capabilities are not a string-keyed registry like events/sources are.

## extensionPoints

- Module entrypoint pattern: export a register<Name>Module() that runs at server bootstrap (mirrors registerCrimeJusticeModule / registerSocialModule). It (a) push()es AffordanceDefinitions into AFFORDANCE_REGISTRY, (b) calls register* functions in event-registry.ts, al.ts, il.ts, evidence.ts, topic-engine.ts, (c) sets up REQUIREMENT_CHECKERS / TARGET_FINDERS / EVIDENCE_SOURCES map entries, (d) declares LLM needs via registerLlmTask.
- For an ECONOMY module (FRAUD/SMUGGLING/TRADE) with NO engine code changes you would register: EVENTS — registerEventCategory('economy',['FRAUD','SMUGGLING','TRADE']), registerEventLabels, registerEventTypeFlags (transferable for FRAUD/SMUGGLING so beliefs gossip), registerEventMoodShifts, registerEventGoalCleanup. AFFORDANCES — push buy/sell/steal/smuggle/defraud AffordanceDefinitions (OCEAN weights, resistTraits honesty:high resists fraud, severity, goalType, declarative stepTemplates) + registerActionVerbs({buy:['buy'],sell:['sell'],defraud:['fraud']...}). STEP LOGIC — registerStepHandler('execute_trade'|'transfer_goods',fn) for anything beyond move/interact. CONSEQUENCES — supply ConsequenceRule[] (FRAUD→VICTIM_RUINED→REVENGE etc.) consumed by ConsequenceEngine; registerBeliefCreator/registerMemoryTextBuilder per consequence type. BELIEFS — registerSourceFlags('ledger_evidence',{firsthand:true}), registerSourceCategory, decay/transfer/labels. REQUIREMENTS — REQUIREMENT_CHECKERS.set('hasCapitalAbove',fn), .set('isMerchant',fn). EVIDENCE — EVIDENCE_RULES.push(...), registerCrimeEvidenceSources-equivalent. CONVERSATION — TOPIC_SOURCE_REGISTRY.push(economyTopics) + registerTopicGroupMapping. HOOKS — registerTickPhaseHandler (price updates / debt accrual / fraud discovery), registerInteractionResultHook (trade settlement), registerDayAdvanceHandler (market drift).
- VERDICT: ~80-90% reachable with NO engine changes — events, affordances, scoring, steps, consequences, beliefs, conversation, evidence, lifecycle hooks are all genuinely registry-driven and the structural import boundary (INV-14) is clean. BLOCKERS forcing engine edits for a real economy: (1) no quantified resource/inventory primitive — buy/sell that actually moves conserved value must be hacked into event.payload + a tick handler (gap); (2) requirement-param channel only forwards beliefConfidence (al.ts:294) so resource-threshold requirements need an engine edit; (3) AgentProfile capability flags are hardcoded booleans (agent-types.ts:101) so new capabilities (canTrade) edit the engine; (4) pre-existing crime-named & half-economy types in engine (CrimeScene/processKill/onMurder; TradeIntent/ShopItem; EmotionalPressure union il.ts:148) mean the module reconciles against, rather than purely extends, the engine.
- RECOMMENDED ENGINE GENERALIZATIONS to widen the genre space (in priority order): (1) Add a generic quantified-RESOURCE/inventory subsystem + RuleCondition op to read it (unlocks economy/combat-HP/politics-influence at once). (2) Rename/abstract CrimeScene→'SceneResidue' (sceneType free string already supported) and processKill→generic state-transition event so combat/economy reuse without crime vocab. (3) Make REQUIREMENT_CHECKERS take a generic params bag from the AffordanceRequirement instead of the beliefConfidence special-case; move the crime-specific typed fields out of the engine AffordanceRequirement interface into module-side typing. (4) Convert AgentProfile capability flags into a string-keyed capability registry (hasCapability already exists as a CG op — extend it to gating). (5) Replace EmotionalPressure.type literal union and TradeIntent category comment with the existing runtime registries as the single source of truth.
