# map-behavioral-core-al-affordances-pm-voliti

> Per-agent structured output (final answer). Raw `.jsonl` transcript alongside.

## area

Behavioral core (AL affordances + PM volition/instinct + CG consequence graph) — genre-generality map

## universal

- CG engine is pure trigger->effect data. cg-types.ts:EventType='string' (no hardcoded union); WorldEvent is generic {type,subject,object,location,importance,payload}. cg-engine.ts:ConsequenceEngine constructor takes a rules array and indexes by trigger type. ZERO crime strings in the whole file. Conditions (RuleCondition) are generic primitives: trait/relationship/belief/has_capability/is_public_place/eq/gt/lt. An Economy rule (e.g. FRAUD -> REPUTATION_LOSS gated on trait/relationship) drops in with no engine change. This is the strongest genre-agnostic component.
- CG target-selection pipeline (cg-engine.ts:resolveTargets/evaluateConditions/isGateCondition) is fully generic: targetMode witnesses|location|affected|all, gate-vs-filter split, exclusive-group per-target priority resolution. None of it knows what a crime is — works equally for 'who reacts to a market crash' or 'who is loyal to a deposed lord'.
- CG side-effects are all registry-dispatched, never inlined: getEventMoodShift, getBeliefCreator, getMemoryTextBuilder, getConsequencePostHandlers (cg-engine.ts:124-136,361-401). Engine calls registries and no-ops/warns on miss. New consequence type = register a creator+text builder+moodshift in a module; engine untouched.
- computeUtility (al.ts:461) is a genuinely genre-neutral linear scorer: personality(OCEAN+H weights) + mood + relationship-sentiment + situational-belief-modifiers + trust, clamped, with optional minimumScore floor. The five contribution channels are abstract drives, not crime motives. An economy affordance scores 'profit' via a high-O/low-A weight set + a beliefModifier on a MARKET_OPPORTUNITY belief; combat scores 'threat' via N + negative-sentiment; politics scores 'influence' via E + trust. The mechanism generalizes directly.
- Affordance dispatch core is data-driven and module-agnostic: AFFORDANCE_REGISTRY, TARGET_FINDERS, REACTIVE_TARGET_FINDERS, REQUIREMENT_CHECKERS, BLOCKING_GOAL_TYPES (al.ts:169-238) are all empty registries filled at startup. findTarget/findReactiveTarget delegate to registry or generic findByRole. checkRegistryRequirements iterates REQUIREMENT_CHECKERS generically (al.ts:288). StepTemplate resolution (volition.ts:resolveTemplates) has a generic default branch that handles ANY module-registered step action via $target resolution + {var:fallback} interpolation — new verbs need no engine code.
- The verb/action vocabulary is dynamic: volition.ts:getVolitionSchema builds the LLM action enum from ENGINE_ACTIONS (go/talk/wait/announce) + getAllRegisteredVerbs() (module verbs). resolveDecision (volition.ts:635) routes engine verbs vs module verbs via getAffordanceIdsForVerb. A module adding 'trade'/'bribe'/'duel' is selectable by the LLM with zero volition.ts edits.
- Instinct intensity x texture engine (instinct-builder.ts) is largely abstract: 7 intensity tiers from score, 3 texture classes selected purely by numeric severity (<=3 emotional, <=6 calculating, >6 primal), 9 Enneagram drive prose, escalation by considerationCount, mood coloring. None of it mentions crime by name — severity is the only coupling knob and severity is module-supplied per affordance.
- Personality model is universal psychology, not crime psychology: OCEAN+H bigFive, Enneagram (coreFear/coreDesire/stressType/growthType). personality-prose.ts:getStressGrowthDirective keys purely off mood thresholds + enneagram type. moodCurve/sentimentCurve produce bidirectional scores (positive mood/sentiment INHIBIT and return negative), so the same curves enable cooperative/social actions, not only antisocial ones.
- Capability-flag pattern for roles (agent-types.ts:102-106 investigator/detersCrime/canSentence) follows the typed-flag-not-string discipline (INV-08-style); the role string is display-only. Adding economy/politics capability flags (e.g. canIssueContract, ownsLand) is the same mechanism.
- Bilateral player/NPC parity is genre-neutral: validatePlayerAction (al.ts:520) reuses the same affordance requirement checks as NPC volition. Works for any module's actions.

## lockedOrLimiting

- al.ts:AffordanceRequirement (lines 11-49) is a crime-justice grab-bag baked into the ENGINE type: hasCrimeBelief, beliefConfidence, isCriminal, isWanted, hasDetainedNpc, hasWitnessBelief, notPerpetrator, hasSuspicionBelief, deductionBelowThreshold, isInvestigator. These should live in the module (checked via REQUIREMENT_CHECKERS registry, which already exists). Their presence as typed engine fields is a direct INV-14 smell — the engine type vocabulary knows about 'crime', 'criminal', 'wanted', 'witness', 'perpetrator', 'deduction'.
- al.ts:checkRequirements / checkRequirementsReactive HARDCODE four crime flags as inline branches BEFORE the generic registry loop: req.notGuard/req.isGuard -> agent.profile.investigator, req.isInvestigator, req.canSentence (al.ts:332-335, 365-368). validatePlayerAction repeats isInvestigator/canSentence with literal strings 'Only investigators can'/'Only judges can' (al.ts:537-541). These are crime-justice role checks compiled into engine control flow, not registry-dispatched — an Economy module cannot remove or reuse them.
- al.ts:checkPostTargetRequirements:303 hardcodes noGuardNearby via other.profile.detersCrime — engine directly reads a crime-deterrence flag. maxWitnesses (line 308) is also a crime-stealth concept living in engine post-target logic. A non-crime module gets 'witness counting' and 'guard avoidance' whether or not it wants them.
- al.ts:findByRole:269-280 (the 'universal' role finder) auto-enriches every target with crime belief fields: it scans beliefs for isTransferable() and writes extra.perpetratorName/affectedName/crimeLocation/crimeType. Comment claims 'harmless if no beliefs' but it bakes crime vocabulary (perpetrator/crime) into the one generic finder all modules share. An economy target finder inherits crime-named extras.
- al.ts:moodCurve:430 is biased toward crime: the doc and math say 'Low H -> enters sliding zone earlier (more crime-prone)', honesty shifts the desperation onset. Mood->action pressure is hardwired to an antisocial-crime model. For a pure economy/trade sim, low mood should not specifically lower the bar via the honesty trait; this couples the engine's core utility curve to a crime narrative. moodWeight is per-affordance (good) but the CURVE SHAPE's H-coupling is engine-level.
- al.ts:StepTemplate (lines 79-105) hardcodes attack/crime fields: reason ('Attack reason template'), lethal?:boolean, beliefTransfer, beliefTransferDirection, evaluateSuspect. goals.ts:GoalStep mirrors evaluateSuspect ('evaluate if target is a suspect... based on guilt + H trait') and beliefTransfer comments say 'transfer relevant CRIME beliefs'. The engine step type vocabulary assumes combat (lethal) and investigation (suspect/guilt).
- volition.ts:buildDecisionPrompt:414 injects agent.profile.secret/innerConflict and Enneagram fear/desire — fine — but the DUTY-blocks-talk mechanic (URGE_THRESHOLD + isDuty, lines 488-497, 'your duty demands it') is a crime-justice interaction model (guard must arrest, can't just chat). isDuty is a generic flag but the 'duty blocks talk' semantics are an engine-level behavioral assumption that may not fit economy/politics.
- agent-types.ts:AgentProfile bakes crime/economy half-primitives directly: investigator/detersCrime/canSentence (crime), shop/ShopItem (a half-built economy primitive — price/inventory) and motive{targetId,reason} described as 'may lead to violence'. These are content concerns sitting in the engine's core agent type. INV-14 test fails: adding Economy shouldn't require these to already exist, and adding Politics would tempt a new hardcoded flag here.
- world.ts (engine) contains crime scene machinery: createCrimeScene, crimeType, perpetratorName/affectedName threading, examination points (world.ts:1078,1386-1563). This is a large crime-specific subsystem living in the engine layer rather than the crime-justice module.

## gaps

- No abstract 'resource/inventory/value' subsystem. Economy needs money, ownership, prices, transactions. Today only ShopItem{price} exists as a half-primitive in agent-types.ts with no transaction ledger, no balance, no transfer-of-value event semantics. A FRAUD/TRADE/SMUGGLING module has nowhere to store or mutate wealth — it would have to invent state outside the engine's agent model.
- Utility scoring channels are fixed to 5 psychological inputs (personality, mood, sentiment, belief-modifiers, trust). There is no generic 'resource-delta' or 'expected-payoff' channel. Economy 'profit' and combat 'win-probability' can only be approximated via beliefModifiers + personality weights; the engine can't natively score 'this action nets +50 gold' or 'I have 70% chance to win this fight'. computeUtility (al.ts:461) would need a pluggable contribution channel (e.g. a SCORING_CONTRIBUTORS registry) to be truly genre-general.
- Instinct texture is selected ONLY by numeric severity into exactly 3 hardcoded classes (emotional/calculating/primal) with crime/violence-flavored prose ('violence', 'the target', 'moral barrier'). There is no registry for texture classes or template sets. An economy 'greed' instinct or a political 'ambition' instinct gets shoehorned into primal/calculating violence prose. Need a TEXTURE/TEMPLATE registry so modules supply their own affect vocabulary (instinct-builder.ts:TEMPLATES is a const, not a registry).
- RESISTANCE_TEMPLATES in instinct-builder.ts are a fixed const keyed to crime/violence resistance (H_high='become this', A_high='do this to another human being', N_high='become the next target'). Resistance prose is not module-extensible; a new genre's moral friction (e.g. betraying an ally, breaking a contract) can't supply its own counter-voice text.
- Reactive volition reactor-selection (volition.ts:206-289) assumes victim-centric grief: requiresRelationToVictim uses event.object as 'victim' and rel.sentiment threshold for 'grief'. No generic notion of 'beneficiary' vs 'harmed party' vs 'rival' — politics/economy events (an alliance, a windfall, a market crash) need richer affected-party typing than subject/object/affectedTargets.
- RuleCondition (cg-types.ts) supports trait/relationship/belief/capability/payload-compare but has no condition over RESOURCES/INVENTORY/STATUS-quantities (e.g. 'target.gold < 10', 'subject owns the contested land'). Economy/politics consequence rules can't gate on world-economic state. has_capability is boolean-only; no quantitative resource conditions.
- Goal/step execution recognizes only built-in actions move_to/interact/interact_present/announce/wait plus generic module steps, but the interact step's value-transfer story is crime-belief-only (beliefTransfer). There is no generic 'transfer N of resource X from A to B' step primitive — every economic exchange would need a bespoke module step handler plus its own state outside the engine.
- No generic faction/group/institution model. Politics needs factions, alliances, hierarchies, allegiance. The engine has pairwise relationships (sentiment/trust) and individual capability flags only. Multi-agent political structures have no engine primitive — they'd be encoded ad hoc in payloads.

## extensionPoints

- Affordances: push AffordanceDefinition records into AFFORDANCE_REGISTRY (al.ts:169). Each record carries weights(OCEAN+H), moodWeight, relationshipWeight, trustWeight, beliefModifiers, severity, resistTraits, stepTemplates, goalType, actionVerb/actionDescription. New genre actions are pure data.
- Target finding: register TargetFinderFn in TARGET_FINDERS / ReactiveTargetFinderFn in REACTIVE_TARGET_FINDERS (al.ts:221-224), keyed by affordance id or targetFinder override; or use declarative targetRole for simple nearest-role lookup via findByRole.
- Requirements: REQUIREMENT_CHECKERS.set(fieldName, fn) (al.ts:229) — checkRegistryRequirements iterates them generically and passes affordance-level params (e.g. minConfidence). This is the intended home for ALL the crime fields currently hardcoded in AffordanceRequirement.
- CG rules: pass ConsequenceRule[] into the ConsequenceEngine constructor (cg-engine.ts:25). New trigger->consequence chains, exclusive groups, and gate/filter conditions are all data. The crime module's CRIME_CG_RULES array is the template.
- CG side-effect registries (event-registry.ts, consumed in cg-engine.ts): registerEventMoodShift, registerBeliefCreator (getBeliefCreator), registerMemoryTextBuilder (getMemoryTextBuilder), registerConsequencePostHandler (getConsequencePostHandlers) — module supplies belief creation, memory prose, mood shift, and arbitrary post-handlers (grief/sentiment) per consequence type.
- Event vocabulary: registerEventCategory + registerEventLabels + registerEventTypeFlagsBatch (isTransferable/isPerpetrator/isFirsthand/subjectReacts) + registerSourceFlags + registerActionVerbs. EventType is an open string; flags drive belief/transfer/reactive behavior without engine edits (INV-08/09/10).
- Steps: registerStepHandler for new step actions; the generic default branch in volition.ts:resolveTemplates already resolves $target/$home/$extra.KEY and interpolates {var:fallback} so most new steps need only a StepTemplate record + a handler. interact step exposes emitEventType to emit a module event after interaction (volition.ts/goals.ts).
- Post-interaction logic: runInteractPostHooks (goals.ts:541) lets modules attach evaluateSuspect-style logic without engine code; the guilt/deduction computation lives in the module hook, not the engine.
- Blocking goals: registerBlockingGoalTypes (al.ts:236) lets a module declare which goal types suppress re-evaluation of a targeted NPC.
- Instinct grounding: per-affordance instinctContext template + target.extra vars (volition.ts:452-456) inject situational prose into the instinct without engine changes — the one currently-available hook for genre-specific flavor in instinct text.
