# CLWA — Движок поведенческой физики

> Физический движок не знает, что такое «машина» — он знает rigid body и силы.
> CLWA не знает, что такое «убийство» — он знает возможности, убеждения и последствия.
> Убийство = данные в модуле. Торговля = данные в модуле. Один движок, разные данные.
> Сюжет не программируется — он возникает из взаимодействия систем.

---

## Проблема

Каждая RPG и MMO за последние 20 лет работает одинаково: дизайнер пишет скрипт, NPC его исполняет. «Поговори с кузнецом» — кузнец говорит заготовленную фразу. «Убей 10 волков» — волки стоят и ждут. NPC не помнит тебя, не имеет мнения, не принимает решений. Мир — декорация.

Три подхода пытались это решить:

| Подход | Что доказал | Чего не хватает |
|---|---|---|
| **Dwarf Fortress** | Тысячи агентов с характером, историей, отношениями | Нет живого диалога — чистые числа |
| **Stanford Generative Agents** | LLM-агенты убедительно живут, планируют, общаются | Нет последствий — NPC «забывает» через 5 минут |
| **Inworld AI / Convai** | Живой диалог с голосом и эмоциями | Нет симуляции мира — NPC существует только в момент разговора |

**CLWA объединяет все три**: глубина симуляции + живой LLM-диалог + причинно-следственный граф, где каждое действие необратимо меняет мир.

---

## Ключевая метафора

**CLWA — движок поведенческой физики.**

Физический движок (Unity, Unreal) не знает, что такое «машина». Он знает rigid body, силу, трение, гравитацию. Машина — это конфигурация: корпус + 4 колеса + двигатель. Движок обрабатывает физику, конкретный объект — данные.

CLWA не знает, что такое «убийство» или «торговля». Он знает:

- **Возможности** — что сущность *может* сделать в данных условиях
- **Личность** — кто сущность *есть* и что её тянет
- **Убеждения** — что сущность *знает* о мире
- **Последствия** — что *произойдёт* после действия
- **Улики** — что *останется* после действия

«Убийство» = возможность (условия: ночь + мотив + отчаяние) + веса личности (низкая честность → сильнее тянет) + правила последствий (свидетели → слухи → розыск) + правила улик (тело + следы + мотив). «Торговля» = другая возможность + другие веса + другие правила. **Тот же движок, другие данные.**

## Как работает NPC

Каждые 15 игровых минут для каждого NPC:

```
Состояние (настроение, убеждения, отношения, местоположение)
  │
  ▼
Affordance Layer — что ФИЗИЧЕСКИ ВОЗМОЖНО прямо сейчас?
  «Ночь + мотив + настроение -0.7 → убийство доступно»
  «Рядом магазин + никого нет → кража доступна»
  │
  ▼
Personality Model — КТО ТЫ? Что тебя тянет?
  Низкая честность → «сильная тяга украсть»
  Высокая совестливость → «чувство долга расследовать»
  │
  ▼
LLM — свободное решение
  NPC получает описание своих «инстинктов» и решает сам.
  Может последовать тяге. Может перешагнуть через неё.
  │
  ▼
Последствия — событие → каскад
  Убийство → свидетели → слухи → розыск → расследование → арест → суд
  │
  ▼
Новое состояние → следующий цикл
```

**Personality Model — это «инстинкт».** Не приказ, а тяга. Числа из психологических моделей (Big Five + Enneagram) определяют, к чему NPC склонен.

**LLM — это «сознание».** Он свободно выбирает из того, что физически возможно. Может подчиниться инстинкту — или преодолеть его. Момент, когда трусливый NPC решает не убегать, а встать и дать показания — не запрограммирован. Он возникает.

## Архитектура: три слоя

```
┌─────────────────────────────────────────────────────┐
│                   Platform Layer                     │
│  Godot клиент · Web UI · Голос · Мультиплеер · API  │
├─────────────────────────────────────────────────────┤
│                World Modules (ДАННЫЕ)                │
│  Crime & Justice · Economy · Politics · Combat · ... │
├─────────────────────────────────────────────────────┤
│                 Engine Core (КОД)                    │
│  Affordances · Personality · Consequences · Evidence │
│  Beliefs · Goals · Memory · Relationships · Perception│
└─────────────────────────────────────────────────────┘
```

**Engine Core** — код. «Законы поведенческой физики.» Подсистемы, которые обрабатывают любое поведение. Не меняется при добавлении контента.

**World Modules** — данные. «Мир, построенный на этой физике.» Каждый модуль — набор записей: какие действия возможны, какие последствия наступают, какие улики остаются. Добавить новое преступление = добавить запись. Добавить экономику = новый модуль. Ноль изменений в движке.

**Platform** — как игрок взаимодействует с миром. Godot, Web, голос — любой клиент поверх одного движка.

## Как создаётся игровой контент

Добавить новый тип поведения = добавить запись данных в модуль:

```
Шантаж:
  Когда возможно:  настроение ниже -0.3, не стражник
  Кого тянет:      нечестных (Honesty < 0.3)
  Что делает:      подойти к жертве → намекнуть на секрет → уйти
  Последствия:     жертва напугана, может сообщить страже
```

Движок сам найдёт подходящего NPC, найдёт цель, покажет «инстинкт» в промпте, даст LLM решить, выполнит шаги, запустит каскад последствий.

Добавить целый модуль «Экономика» (торговля, крафт, контрабанда) = набор таких записей + правила последствий. Движок обработает всё теми же подсистемами.

### Что это значит для разработки игры

| Традиционный подход | CLWA |
|---|---|
| Дизайнер пишет квест: «иди туда, убей того» | Дизайнер создаёт *условия*: NPC с мотивами, мир с возможностями |
| Каждый сценарий — отдельный скрипт | Сценарии *возникают* из взаимодействия систем |
| 100 квестов = 100 скриптов | 100 возможностей × 50 NPC = тысячи уникальных историй |
| Новый контент = программист пишет код | Новый контент = дизайнер заполняет таблицы данных |
| NPC повторяет одни и те же фразы | NPC помнит, реагирует, меняется |

## Подсистемы движка

### AL — Affordance Layer (Слой возможностей)

Определяет, что NPC **физически может** сделать прямо сейчас. Как гравитация определяет, куда может упасть объект — AL определяет пространство возможных действий.

Ночь + рядом магазин + никого нет → «кража» доступна. День + стражник рядом → кража невозможна. NPC не думает о том, что не может сделать — он даже не знает об этой возможности, пока условия не сложатся.

Каждая возможность — декларативная запись: условия, кого тянет (веса личности), шаги выполнения. Новое поведение = новая запись. Ноль кода.

### PM — Personality Model (Модель личности)

Определяет, **кто** NPC и к чему его тянет. Как масса определяет инерцию тела.

Два слоя: **Big Five + Honesty** (шесть числовых шкал 0–1: открытость, дисциплина, экстраверсия, доброта, тревожность, честность) определяют *как* NPC поступает. **Enneagram** (тип + крыло) определяет *почему* — глубинный страх и желание.

PM не выбирает действие — он формирует **ощущение тяги** в промпте LLM: «тебя сильно тянет украсть» или «на краю сознания мелькает мысль о покаянии». LLM решает сам. PM = инстинкт, LLM = сознание.

### CG — Consequence Graph (Граф последствий)

Каскадные правила: событие → цепочка реакций. Как столкновение бильярдных шаров — одно событие порождает серию других.

`Убийство при свидетелях → свидетель запоминает → слух в публичном месте → слух доходит до стражи → розыск`. Каждое звено — отдельное правило. Правила комбинируются автоматически. Последствие одного правила может стать триггером другого.

### EL — Evidence Layer (Слой улик)

Когда происходит событие, EL создаёт **структурированные улики** на локации: тело, следы, мотив, возможность. Как следы торможения на асфальте после аварии.

Стража приходит на место → осматривает улики → формирует подозрения из данных (кто был на месте + у кого мотив), а не из скрипта. Преступник может уничтожить улики до прихода стражи — и расследование пойдёт сложнее.

### Belief System (Убеждения)

Что NPC **знает** о мире — структурированные факты с уровнем уверенности и источником. Как объект «знает» свою скорость и позицию.

«Mark убил Bess, уверенность 0.7, источник: показания свидетеля.» Разные источники сосуществуют: свидетельство + улики + слухи. Уверенность накапливается или затухает со временем. Убеждения управляют поведением: стражник с belief (confidence ≥ 0.7) может арестовать, ниже — продолжает расследование.

### Goal System (Цели)

Многошаговые планы: «пойти на место преступления → осмотреть улики → допросить свидетелей → объявить розыск → вернуться». Как траектория объекта в поле сил — серия шагов к цели.

Цели имеют приоритет: срочное расследование прерывает рутинный патруль. Цели создаются автоматически из affordances и событий — не скриптуются вручную.

### Memory System (Память)

Каждый NPC хранит воспоминания в векторной базе данных. Как история всех состояний объекта.

При разговоре NPC вспоминает релевантное: «Три дня назад я видел Mark у храма ночью» — не потому что скрипт сказал вспомнить, а потому что семантический поиск нашёл это воспоминание. Старые воспоминания тускнеют, яркие (важность 8+) держатся дольше. NPC периодически рефлексирует — обобщает опыт в инсайты.

### Relationship System (Отношения)

Направленные связи между NPC: тип (друг, коллега, соперник), настроение (sentiment -1..+1), доверие (trust 0..1). Как пружины и шарниры между объектами.

Отношения влияют на всё: свидетель-друг убийцы может покрывать его. Стражник с низким trust к игроку не поверит показаниям. Доверие растёт, когда слова подтверждаются фактами, и падает, когда опровергаются.

### IL — Intent Layer (Слой речи)

Инверсия диалога: обычный чат превращает состояние NPC → текст для игрока. IL превращает текст игрока → структурированный смысл для движка. Как внешняя сила, приложенная к системе.

«Я видел, как Mark убил Bess» → IL извлекает: claim (eventType: убийство, subject: Mark, object: Bess, confidence: 0.9). Движок создаёт belief в NPC с учётом доверия к игроку. Если trust = 0.3 → effective confidence = 0.27 (слабый слух). Если trust = 0.8 → confidence = 0.72 (достаточно для расследования).

### Perception (Восприятие)

Что NPC видит и слышит. Как зона обнаружения столкновений.

NPC видит только тех, кто на той же локации. Слышит соседние. Если преступление совершено без свидетелей — никто не узнает, пока не найдут тело или улики. Стелс, подслушивание, слепые зоны — всё через одну систему.

---

Все подсистемы **независимы и комбинируемы**. Один NPC может быть торговцем утром, шпионом вечером и убийцей ночью — без единой строки скрипта. Каждая комбинация возможностей + личности + ситуации = уникальное поведение.

## Игрок в мире

Игрок — не «турист», наблюдающий за симуляцией. Он **полноценная сущность мира**:

- Говорит с NPC свободным текстом → движок извлекает смысл → создаёт убеждения в NPC
- «Я видел, как Mark убил Bess» → NPC получает belief, может начать расследование
- NPC формирует мнение об игроке, доверие растёт или падает
- NPC сам подходит к игроку, если есть что сказать
- NPC обсуждают игрока между собой

Та же система, что обрабатывает NPC→NPC общение, обрабатывает Player→NPC. Те же убеждения, та же память, те же последствия.

## Что уже работает

Деревня из 8 NPC. У каждого — характер, расписание, секрет, отношения. Они:

- **Живут** по расписанию: кузнец куёт, бард поёт, стражник патрулирует
- **Разговаривают** друг с другом: темы выбираются на основе реального состояния мира
- **Принимают решения**: LLM свободно выбирает из того, что возможно
- **Совершают преступления**, если условия сходятся — кража, убийство, самосуд
- **Обнаруживают** тела, распространяют слухи
- **Расследуют**: стража идёт на место, собирает улики, допрашивает
- **Арестовывают**, судят, выносят приговор
- **Помнят** всё: каждый разговор, каждое событие, каждую эмоцию

Полная цепочка от преступления до приговора возникает без единого скрипта. Кто совершит преступление, когда, против кого — определяется состоянием мира, не сценарием.

## Жанр и возможные поджанры

**Название жанра**: Emergent Narrative Simulation — симуляция эмерджентного нарратива. Для маркетинга короче: **Living World RPG** или **Narrative Physics**.

Все поджанры ниже — не отдельные игры. Это **модули данных на одном движке**. Комбинируются: NPC-торговец днём может быть контрабандистом ночью, а его арест вызовет политический кризис, потому что он — советник мэра.

| Поджанр | Суть | Как ощущается |
|---|---|---|
| **Emergent Detective** | Расследование преступлений, которые не заскриптованы. Каждый раз другой убийца, мотив, свидетели | Disco Elysium, но каждый playthrough — новое дело |
| **Political Sandbox** | Фракции, выборы, заговоры, революции — всё из отношений и амбиций NPC | Crusader Kings, но каждый NPC — живой |
| **Economic Simulation** | Торговля, дефицит, контрабанда, монополии — NPC реагируют на цены | Eve Online экономика с живыми торговцами |
| **Social Drama** | Романы, предательства, дружба, месть | The Sims с настоящей памятью и последствиями |
| **Survival Community** | Группа выживает — NPC помогают, предают, жертвуют | Rimworld, но ты внутри, а не сверху |
| **War & Diplomacy** | Сражения, альянсы, шпионаж | Total War, но каждый офицер — личность с мотивами |
| **Emergent Horror** | Паранойя распространяется, доверие разрушается | Among Us, но никто не знает кто «оно» — включая сюжет |
| **Mentor / Teacher** | Игрок обучает NPC, NPC учат друг друга, строят цивилизацию | Black & White, но NPC учат друг друга |
| **Living MMO** | Мир помнит каждого игрока, репутация — реальная | WoW, но NPC помнят что ты сделал 3 месяца назад |

## Дорожная карта

### Phase 1: Proof of Concept ✅

> Доказать, что эмерджентный нарратив работает.

Деревня, 8 NPC, модуль Crime & Justice. Полная цепочка: преступление → свидетели → слухи → расследование → арест → суд → приговор. Всё эмерджентно.

### Phase 2: Player Integration ✅

> Игрок — полноценная сущность мира, а не турист.

Intent Layer: речь игрока → structured meaning → beliefs в NPC. Trust эволюционирует. NPC подходят к игроку сами. NPC обсуждают игрока между собой.

### Phase 3: World Expansion — следующая

> Новые подсистемы движка + модули контента. Подробности: [ROADMAP.md](ROADMAP.md)

Движку нужны 4 новые подсистемы:

| Подсистема | Суть | Что разблокирует |
|---|---|---|
| **Trauma** | Необратимые сдвиги личности от экстремальных событий | Character arcs, Horror, глубокий Social |
| **Inventory** | Физические предметы: владение, передача, кража | Реальная экономика, крафт, улики-предметы |
| **Needs** | Голод, усталость, жадность — давление поверх mood | Organic мотивация, Survival, спрос |
| **Factions** | Группы с иерархией, общими beliefs, репутацией | Политика, семьи, организованная преступность |

Эти 4 + существующие 10 = достаточно для модулей Economy, Politics, Social, Survival.

### Phase 4: Scale & Multiplayer

> От одного игрока в деревне к сотням NPC и десяткам игроков. Подробности: [ROADMAP.md](ROADMAP.md)

| Подсистема | Суть |
|---|---|
| **NPC Scaling** | Три уровня: hot (полный LLM), warm (числа), cold (минимум). 1000 NPC, hot только 5-15 ближайших |
| **Combat** | Три уровня ИИ: мобы (behaviour tree), элитные (ML), боссы (ML combat + LLM рефлексия между фазами) |
| **Reputation** | Агрегированное мнение фракций вместо 1000 индивидуальных отношений |
| **Territory** | Зоны контроля фракций, захват, влияние |
| **Multi-player** | Каждый игрок = Agent. NPC формируют мнение о каждом отдельно |

### Phase 5: Living MMO — видение

> Persistent мир, где каждое действие каждого игрока необратимо меняет историю.

1000+ NPC, 100+ игроков на зону. Динамические мировые события из состояния мира. Эмерджентные квесты из потребностей NPC. Экономика с обратной связью. Фракции игроков. Летопись из тысяч реальных событий.

## Для команды — что нужно знать каждому

### Сценаристу

**Главное**: ты больше не пишешь сюжет. Ты проектируешь давление.

Твоя работа — не написать квест «Mark убивает Bess». Твоя работа — создать Mark'а с долгами, Bess которая знает его секрет, и ненависть -0.7 между ними. Дальше мир сам решит — убьёт, украдёт, сбежит, или вообще помирятся после хорошего разговора. Каждый запуск — другая история.

**Твои инструменты вместо скриптов:**

- **Характеры** — шесть числовых шкал (честность, тревожность, экстраверсия...) + мотивационное ядро (глубинный страх и желание). Не «Mark злой» — а «Mark нечестен (H=0.2), тревожен (N=0.6), боится быть никчёмным (Enneagram 3)». Из этого движок сам выведет поведение.
- **Голос** — ты не пишешь реплики. Ты пишешь speechStyle: примеры, манеры, как NPC говорит когда нервничает vs когда расслаблен. LLM генерирует диалог в этом стиле.
- **Секреты и конфликты** — secret (что NPC скрывает), innerConflict (что его разрывает), motive (на кого он злится и почему). Это топливо для эмерджентных историй.
- **Отношения** — кто кого любит, ненавидит, боится, кому должен. Начальная сеть tensions.
- **Начальные условия** — кто где живёт, стартовое настроение, расписание дня.

Сценарий демки — это не «в 19:00 Mark идёт к Bess». Это таблица: 8 NPC, у каждого мотивы, секреты, конфликты с другими. Ты задаёшь пороховую бочку — мир поджигает фитиль.

**Мышление системами**: «если добавить этот секрет + эту обиду + этот мотив → какие ВОЗМОЖНЫЕ истории могут возникнуть?» Не одна история — веер.

Читать дальше: таблица NPC профилей в [ARCHITECTURE.md](ARCHITECTURE.md), примеры DialogueMeaning в [ROADMAP.md](ROADMAP.md).

### Программисту

**Главное**: engine не знает ни одного конкретного события, статуса, роли. Всё через регистры.

**Архитектура — три пакета:**
- `engine/` — код, «законы физики». Пустые регистры, универсальные подсистемы.
- `modules/` — данные, «мир на этой физике». Заполняет регистры при старте.
- `server/` — платформа. HTTP/WS, bootstrap, NPC профили.

Зависимости: modules → engine, server → engine + modules. **Engine НИКОГДА не импортирует из modules.**

**Правила, нарушение которых ломает архитектуру:**
- Строка `'NPC_KILLED'` в engine — нарушение. Модуль регистрирует event type, engine работает с ним через flags и registries.
- Новый функционал = запись данных в module, не код в engine. Если нужно менять engine — сначала проверь, есть ли registry.
- Все типы = string (EventType, NpcStatus, BeliefSource). Нет TypeScript union'ов. Modules определяют значения через `registerXxx()`.
- LLM semaphore: `acquire()` → call → `release()` в finally. Concurrency = 1.
- Перед изменением функции: `find_referencing_symbols`. Без трассировки зависимостей не редактировать.
- null = «неизвестно». Никогда строка-заглушка вместо null.

Читать обязательно: [CLAUDE.md](CLAUDE.md) — принципы и инварианты. Это библия проекта.

### Дизайнеру

**Главное**: игрок не видит систему — он видит живой мир. Магия в непрозрачности.

Числа (mood -0.6, belief confidence 0.7) существуют под капотом. Игрок видит поведение: NPC нервничает, подходит с новостью, отказывается говорить, дрожит при допросе. Это LLM генерирует из mood через промпт — не анимация, а текст и голос.

**Что показывать:**
- Trust bar в диалоге — одно из немногих чисел, которые можно обнажить. Как «отношение» в Mass Effect.
- Notifications для ключевых событий: убийство, арест, приговор. Редкие, крупные, драматичные.
- Crime scene — не UI-экран с кнопками, а место в мире. Приходишь, осматриваешь, каждая точка — текст из structured data.
- NPC подходит к тебе сам — это самый сильный сигнал «мир живой».

**Что НЕ показывать:**
- Mood числом. Вместо «-0.6» — поведение: бегающий взгляд, резкие ответы, трясущиеся руки.
- Belief списком. Вместо «confidence 0.7» — NPC говорит «Я уверен, это был Mark» или «Ходят слухи, но я не уверен».
- Affordance scores. Игрок не должен знать, что у Mark score 0.84 на kill. Он должен видеть, что Mark ведёт себя странно.

**Твоя ручка баланса** — это числа, не скрипты:
- `moodBias: -0.03` = мрачный мир, преступления чаще. `+0.02` = мирный.
- `kill threshold: -0.6` = редкое убийство. `-0.3` = хаос.
- Начальные mood'ы NPC = насколько «заряжена» ситуация с самого старта.

Ты балансируешь атмосферу числами. Мир реагирует сам.
