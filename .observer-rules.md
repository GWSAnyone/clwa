# Observer Rules: CLWA

## Checklist (verify each on every code change)

### Engine/Module boundary (Rules 2-3, Invariants 1-12)
- [ ] No file in `packages/engine/` imports from `packages/modules/`
- [ ] No hardcoded event type, role, status, verdict, speech act, claim source, or pressure type string in engine code
- [ ] No `?? 'HARDCODED_STRING'` fallback on typed fields in engine
- [ ] No `role === 'guard'` or similar — use capability flags (profile.investigator, etc.)
- [ ] New behavior = data record in module, zero engine code changes

Typical mistakes:
- Adding `if (eventType === 'NPC_KILLED')` in engine — should use `isTransferable(eventType)` or other boolean flag from registerEventTypeFlags()
- Adding `?? 'BODY_DISCOVERED'` fallback — if registry returns null, skip or throw, never hardcode
- Checking `agent.profile.role === 'guard'` — use `agent.profile.investigator` capability flag
- Adding new case to engine switch/if instead of registering in STEP_HANDLERS, EVENT_HANDLERS, etc.

### Mood system (Rule 73, SPEC-mood-modifiers)
- [ ] No `agent.state.mood +=` or `agent.state.mood =` anywhere — always `World.addModifier()`
- [ ] Mood modifiers have {source, category, magnitude, duration, decay}

Typical mistakes:
- Quick fix `agent.state.mood -= 0.1` instead of creating a MoodModifier with proper source/category/decay
- Forgetting that mood is COMPUTED: effectiveMood = baseMood + Σ(modifiers). Direct mutation breaks the system.

### Async discipline (Rules 1, 7)
- [ ] LLM semaphore: acquire() → call → release() in `finally` block
- [ ] `handleEventForGoals` is always `await`ed — never fire-and-forget

Typical mistakes:
- `handleEventForGoals(...)` without await — promise result silently dropped, goals never process the event
- LLM semaphore released in normal path but not in catch/error path — deadlocks on next LLM call
- Missing `finally` block — if LLM call throws, semaphore stays acquired forever

### Bilateral design (Rule 5, Invariant 21)
- [ ] Every `for (agent of agents)` loop has explicit `isPlayer` guard decision
- [ ] NPC-only loops: volition, schedule, night walks, goal processing, conversation pairs
- [ ] Bilateral loops (include player): body discovery, perception, mood shifts

Typical mistakes:
- New agent loop without `if (agent.isPlayer) continue` or explicit inclusion — player accidentally gets NPC-only processing (volition, auto-movement) or misses bilateral events (mood shifts, perception)
- Adding NPC name to LLM conversation list without filtering `isPlayer` — player name leaks into NPC prompts

### State discipline (Rules 9, 56)
- [ ] `processingState` is transient — never persisted to save.json
- [ ] `inPlayerChat` cleared in finally block
- [ ] `status === null` means free — no 'free' string in engine

Typical mistakes:
- Adding `processingState` to toJSON() — transient state appears in save, NPCs load as "stuck" in old state
- Setting `inPlayerChat = true` without try/finally — if chat handler throws, NPC permanently frozen
- Checking `status === 'free'` instead of `status === null` or `!isStatusAbsent(status)`

### Registry pattern (Rules 3, 5, 6)
- [ ] All event types, statuses, verdicts = registry lookups, never inline strings
- [ ] Engine checks boolean flags (isTransferable, isPerpetrator, etc.), not category strings
- [ ] New step types via STEP_HANDLERS registry, not engine switch/if

Typical mistakes:
- Adding `case 'examine_scene':` to engine's executeStep switch — should register via STEP_HANDLERS
- Checking `belief.source === 'WITNESS'` in engine — should use `isFirsthand(source)` flag
- Adding new event type handling with `if (type === 'THEFT')` — should use registered flags

### Belief transfer (Invariant 14)
- [ ] Dedup key = (eventType, object) — not (eventType, subject, object)
- [ ] Use `transferBeliefs()` helper from goals.ts — don't duplicate the loop
- [ ] Transfer confidence = source confidence × getSourceTransferWeight(source)

## Architecture context

```
Engine  (packages/engine/)  — universal subsystems, 40+ empty registries, ZERO module content
Modules (packages/modules/) — world content via registration functions
  ├── social/              — universal social topic sources
  └── crime-justice/       — crime affordances, CG rules, step handlers
Server  (packages/server/)  — HTTP/WS, world-loader, bootstrap
```

Dependencies: modules → engine, server → engine + modules. Engine NEVER depends on modules.
